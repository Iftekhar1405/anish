## Protocol (every agent + developer MUST follow)

1. **On start:** `git pull`, then **read this file first**, then `memory.md`. Begin from **Next Steps** below.
2. **Pick one thing** from Next Steps. If another owner is listed as active on it (see Active Ownership), coordinate — don't double-work.
3. **Work one phase at a time** (see `phases.md`); update docs before code; verify/test before claiming done.
4. **Before every push:** update the four rolling sections below (**Current Status · In Progress · Next Steps · Blockers**) and add a **Handoff Log** entry (newest on top). Update `memory.md` if a decision or phase status changed.
5. **Branch per unit of work** (e.g. `phase-1-foundation`); open a PR; note branch/PR in Current Status. Never leave `master` in a broken state.
6. Leave the repo so the next person can `pull` and continue with zero context loss.

- **Device-feedback fix pass — CODE-COMPLETE, pending re-check on the device.** Branch `fix/ui-scroll-tap-icons` (continues on top of the earlier UI pass). Driven by a list of defects reported from an actual Android phone.
  - ✅ **Session handling (`packages/api-client`) — the root cause behind three separate reports.** Refresh is now **single-flight**: previously every query on a screen fired its own refresh when the access token expired, the first rotated the refresh token and the rest presented an already-used one, so the server's **reuse detection revoked the whole family** and the user was logged out. That's "airplane mode on/off logs me out" (reconnect ⇒ a burst of simultaneous retries), and it also produced stray `Missing bearer token` errors. On top of that: a `NetworkError` type now separates "couldn't reach the server" from "not authorised" so **being offline never clears tokens**; the client **refreshes pre-emptively** when the access token is missing instead of spending a guaranteed-401 round trip on it (a likely contributor to the "admin list takes ages to load until you tap a status filter" report); a genuinely dead session calls `onSessionExpired`, which each app's `AuthProvider` turns into a clean logout + redirect to login rather than error text on every screen; and React Query no longer retries 4xx, so real errors surface immediately instead of after two backoffs.
